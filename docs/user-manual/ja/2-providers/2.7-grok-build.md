# 2.7 Grok Build

## 概要

[Grok Build](https://www.npmjs.com/package/@xai-official/grok) は xAI のコーディング CLI です。v3.17.0 から、CC Switch は Grok Build を Claude Code・Codex・Gemini CLI と同等のアプリとして管理します：

| 機能 | 対応状況 |
|------|----------|
| プロバイダー切り替え | 対応。`~/.grok/config.toml` に書き込み |
| MCP サーバー | 対応。`config.toml` の `[mcp_servers]` テーブルに保存 |
| Skills | 対応。`~/.grok/skills/` にインストール |
| プロンプト | 対応。`~/.grok/AGENTS.md` に書き込み |
| セッションマネージャー | 対応。`~/.grok/sessions/` と `~/.grok/archived_sessions/` を読み取り |
| ローカルプロキシのテイクオーバーとフェイルオーバー | 対応 |
| CLI のインストール / 更新 | 対応。設定 → バージョン情報 から実行（`npm i -g @xai-official/grok@latest`） |
| プロジェクト（Profiles） | 非対応（プロジェクトは Claude Code、Claude Desktop、Codex が対象） |

アプリ切り替えに Grok Build が表示されない場合は、**設定 → 一般 → ホームページ表示** で有効にしてください。

## 設定ファイル

Grok Build は 1 つの TOML ファイルを読み込みます。CC Switch はそのうちモデル選択の部分を管理し、同じファイル内の MCP サーバーは MCP ページから管理します。

```toml
[models]
default = "grok-4.5"            # Grok Build が使用するクライアントモデルプロファイル

[model."grok-4.5"]
model = "grok-4.5"              # プロバイダーに送信するモデル名
name = "My Provider"
base_url = "https://api.example.com/v1"
api_key = "sk-..."              # または env_key = "MY_PROVIDER_API_KEY"
api_backend = "responses"       # responses / chat_completions / messages
context_window = 500000
```

プロバイダーを保存する前に、CC Switch はファイルを検証します。`[models].default` が指すテーブルが存在し、`model`、`base_url`、`name`、`api_backend`、正の整数の `context_window`、および `api_key` または `env_key` のいずれかを含んでいる必要があります。

設定ディレクトリは **設定 → 詳細 → 設定ディレクトリ → Grok Build 設定ディレクトリ**（`settings.json` の `grokConfigDir`）で変更できます。

## プロバイダーの追加

1. アプリ切り替えで **Grok Build** を選択
2. 右上の **+** をクリック
3. プリセットを選ぶか、**カスタム** を選択

Grok Build は Codex のサードパーティプリセットを再利用します（OpenAI 公式のエントリは表示されません）。多くの OpenAI 互換ゲートウェイをワンクリックで追加できます。

### フォーム項目

| 項目 | `config.toml` のキー | 説明 |
|------|----------------------|------|
| 名前 | `name` | 表示名。モデルテーブルにも書き込まれる |
| API Key | `api_key` | ファイルに直接保存。生エディターで `env_key` を使う場合は空欄で可 |
| エンドポイント | `base_url` | プロバイダーのベース URL |
| クライアントモデルプロファイル | `[models].default` | Grok Build が選択するプロファイル名。デフォルト `grok-4.5` |
| モデル | `model` | 上流に送信するモデル。デフォルトはプロファイル名と同じ |
| API バックエンド | `api_backend` | `responses`（デフォルト）、`chat_completions`、`messages`（Anthropic Messages） |
| コンテキストウィンドウ | `context_window` | 正の整数。デフォルト `500000` |

フォーム下部の **config.toml** エディターにはドキュメント全体が表示され、どちらで編集しても同期されます。TOML が不正な場合は保存できません。

## プロバイダーの切り替え

プロバイダーカード、メイン画面、トレイメニューから切り替えられます。CC Switch は `~/.grok/config.toml` のモデルテーブルを書き換え、`[mcp_servers]` のエントリはそのまま残します。切り替え後、新しいプロバイダーを反映するために **Grok Build を再起動** するよう通知されます。

## ローカルプロキシとの併用

Grok Build も Claude Code・Codex・Gemini CLI と同様にローカルプロキシでテイクオーバーできます：

- プロキシパネルで **Grok Build** のテイクオーバースイッチをオンにする（[4.2 アプリケーションルーティング](../4-proxy/4.2-routing.md) を参照）
- テイクオーバー中、`base_url` は `http://127.0.0.1:<ポート>/grokbuild/v1` を指し、リクエストは現在のプロバイダー経由で転送される
- フェイルオーバーキュー、サーキットブレーカー、使用量統計は他のアプリと同じように動作する（[4.3 フェイルオーバー](../4-proxy/4.3-failover.md) を参照）

## トラブルシューティング

| 問題 | 解決方法 |
|------|----------|
| 「Grok Build configuration is missing [models]」と表示される | 生の `config.toml` に `[models]` テーブルがありません。フォーム項目を入力し直すか、`[models] default = "..."` を追加してください |
| 「missing a valid api_key or env_key field」と表示される | API Key を入力するか、`env_key` にキーを保持する環境変数名を設定してください |
| 切り替えが反映されない | Grok Build を再起動してください。`config.toml` は起動時にのみ読み込まれます |
| Grok Build に MCP サーバーが表示されない | MCP の同期は `~/.grok/` が存在する場合のみ行われます。Grok Build を一度起動してから、MCP ページで Grok Build 向けにサーバーを有効にしてください |
