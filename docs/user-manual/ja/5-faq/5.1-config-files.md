# 5.1 設定ファイルの説明

## CC Switch のデータストレージ

### ストレージディレクトリ

デフォルトの場所：`~/.cc-switch/`

設定で場所を変更できます（クラウド同期フォルダなど）。選択したパスは Tauri の `app_paths.json` ストアに記録されます。`settings.json` は常に `~/.cc-switch/` に残ります。

### ディレクトリ構造

```
~/.cc-switch/
├── cc-switch.db      # SQLite データベース（SSOT）
├── settings.json     # デバイスレベルの設定
├── skills/           # スキル SSOT ディレクトリ
├── skill-backups/    # スキルバックアップ（アンインストール時に作成）
├── backups/          # データベースバックアップ（db_*.db）
│   └── <app>/        # CC Switch がライブ設定ファイルを上書きする前に保存したコピー
└── logs/             # cc-switch.log（アプリログ）と crash.log
```

### データベースの内容

`cc-switch.db` は SQLite データベースで、以下を保存しています：

| テーブル | 内容 |
|-----|------|
| providers | プロバイダー設定（アプリごと） |
| provider_endpoints | プロバイダーエンドポイント候補リスト |
| mcp_servers | MCP サーバー設定とアプリごとの有効化状態 |
| prompts | プロンプトプリセット |
| skills | インストール済みスキルとアプリごとの有効化状態 |
| skill_repos | スキルリポジトリ一覧 |
| profiles | プロジェクト（プロバイダー / MCP / スキル / プロンプト状態の名前付きスナップショット） |
| settings | データベースと一緒に同期されるキー・バリュー状態（共通設定スニペット、現在のプロジェクトなど） |
| proxy_config | ローカルプロキシ、フェイルオーバー、サーキットブレーカーの設定（プロキシ対象アプリごとに 1 行） |
| proxy_live_backup | プロキシがテイクオーバーしている間の各アプリの Live 設定のバックアップ |
| provider_health | プロバイダーのヘルス / フェイルオーバー状態 |
| proxy_request_logs | リクエストごとの使用量ログ（プロキシとセッション同期） |
| usage_daily_rollups | 詳細ログ削除後も残る日次使用量集計 |
| session_log_sync | 使用量統計に取り込む CLI セッションログの読み取り位置 |
| stream_check_logs | プロバイダーのストリーミングヘルスチェック結果 |
| model_pricing | コスト計算に使うモデル料金 |

### デバイス設定

`settings.json` はデバイス間で同期**されない**デバイスレベルの設定を保存します。キーは camelCase で、`src-tauri/src/settings.rs` の `AppSettings` と一致します。未設定のキーはファイルに書き込まれません。典型的な内容：

```json
{
  "showInTray": true,
  "minimizeToTrayOnClose": true,
  "useAppWindowControls": false,
  "launchOnStartup": false,
  "silentStartup": false,
  "language": "en",
  "visibleApps": {
    "claude": true,
    "claude-desktop": true,
    "codex": true,
    "gemini": true,
    "grokbuild": true,
    "opencode": true,
    "openclaw": true,
    "hermes": false
  },
  "enableClaudePluginIntegration": false,
  "skipClaudeOnboarding": false,
  "enableLocalProxy": false,
  "enableFailoverToggle": false,
  "showProfileSwitcher": true,
  "preserveCodexOfficialAuthOnSwitch": false,
  "unifyCodexSessionHistory": false,
  "claudeConfigDir": "/custom/path/.claude",
  "currentProviderClaude": "my-provider-1730000000000",
  "skillSyncMethod": "auto",
  "skillStorageLocation": "cc_switch",
  "backupIntervalHours": 24,
  "backupRetainCount": 10,
  "preferredTerminal": "iterm2"
}
```

主なキー：

| キー | デフォルト | 意味 |
|------|-----------|------|
| `showInTray` / `minimizeToTrayOnClose` | `true` / `true` | トレイアイコン、閉じるボタンで終了せずトレイに隠す |
| `useAppWindowControls` | `false` | アプリ独自のタイトルバーボタンを使う |
| `launchOnStartup` / `silentStartup` | `false` | ログイン時に起動、トレイのみで起動 |
| `language` | システム | `en`、`zh`、`zh-TW`、`ja` |
| `visibleApps` | Hermes 以外すべて | メイン画面に表示するアプリ |
| `enableClaudePluginIntegration` | `false` | Claude Code VS Code 拡張も切り替える |
| `skipClaudeOnboarding` | `false` | Claude Code の初回起動確認をスキップ |
| `enableLocalProxy` / `enableFailoverToggle` | `false` | メイン画面にローカルプロキシとフェイルオーバーのスイッチを表示 |
| `showProfileSwitcher` | `true` | ヘッダーにプロジェクト切り替えを表示 |
| `preserveCodexOfficialAuthOnSwitch` / `unifyCodexSessionHistory` | `false` | Codex の公式ログインとセッション履歴のオプション |
| `claudeConfigDir`、`codexConfigDir`、`geminiConfigDir`、`grokConfigDir`、`opencodeConfigDir`、`openclawConfigDir`、`hermesConfigDir` | 未設定 | 各ツールの設定ディレクトリを上書き |
| `currentProvider<App>` | 未設定 | このデバイスでのアプリごとの現在のプロバイダー ID（データベースより優先） |
| `skillSyncMethod` / `skillStorageLocation` | `auto` / `cc_switch` | スキルの同期方式（`auto`、`symlink`、`copy`）と保存場所（`cc_switch` または `unified` = `~/.agents/skills/`） |
| `webdavSync` / `s3Sync` | 未設定 | クラウド同期設定（認証情報を含む） |
| `backupIntervalHours` / `backupRetainCount` | `24` / `10` | データベース自動バックアップの間隔（`0` で無効）と保持数 |
| `preferredTerminal` | システム既定 | セッションを開くターミナル |

`proxyConfirmed`、`usageConfirmed`、`failoverConfirmed`、`firstRunNoticeConfirmed`、`commonConfigConfirmed` は閉じた初回通知を記録し、`localMigrations` はこのデバイスで実行済みの一回限りの移行を記録します。

UI テーマは `settings.json` には**ありません**。アプリのブラウザストレージ（`localStorage` のキー `cc-switch-theme`）に保存されます。

### 自動バックアップ

`backups/` ディレクトリに自動バックアップが保存されます：

- 定期的に作成（`backupIntervalHours` ごと、デフォルト 24 時間）、およびデータベース移行と SQL インポートの前に作成
- ファイル名はバックアップの種類で始まる：`db_backup_`（定期）、`db_manual_`（今すぐバックアップ）、`db_safety_`（インポート・同期ダウンロード・復元の前）、`db_premigration_`（スキーマのアップグレード前）
- 種類ごとに最新の `backupRetainCount` 件を保持（デフォルト 10 件）。手動バックアップと名前を変更したバックアップは自動削除されない
- 設定画面から復元・名前変更・削除が可能（[1.5 個人設定](../1-getting-started/1.5-settings.md) を参照）

### ライブ設定ファイルのバックアップ

CC Switch はツールのライブ設定ファイルを上書きする前に（プロバイダーの切り替え時など）、現在のファイルを `~/.cc-switch/backups/<app>/<名前>_<タイムスタンプ>.<拡張子>` にコピーします。対象は Claude の `settings.json`、Codex の `auth.json` と `config.toml`、Gemini の `.env` と `settings.json` です。前回のコピーから変更がない場合はコピーされず、保持数は `backupRetainCount` に従います。

ライブファイルを解析できない場合（手動編集で構文エラーになった Gemini の `settings.json` など）、新しいファイルで置き換えずに、ファイル名を示すエラーで切り替えを中止します。秘密情報を含むファイル（Claude `settings.json`、Codex `auth.json` / `config.toml`）は、所有ユーザーのみが読み取れる権限で作成されます。

### settings.json の破損

起動時に `~/.cc-switch/settings.json` を解析できない場合、CC Switch はそれを `settings.json.corrupt-<タイムスタンプ>` にリネームしてエラーを記録し、デフォルト設定で起動します。元のファイルは残っているので、修復してから戻すことができます。

### アプリが起動しないときの手動復元

アプリが動作している間は、設定 → 詳細 → バックアップと復元 の **復元** ボタンを使ってください。データベースが破損して CC Switch が起動しなくなった場合は、次の手順で手動復元します。

1. CC Switch を完全に終了します（トレイアイコン → 終了。`cc-switch` プロセスが残っていないことを確認）。
2. データディレクトリを開きます: `~/.cc-switch`（Windows: `%USERPROFILE%\.cc-switch`）。
3. 現在のデータベースを退避して残しておきます: `cc-switch.db` を `cc-switch.db.broken` にリネームし、`cc-switch.db-wal` と `cc-switch.db-shm` があれば同様にリネームします。
4. `backups/` から問題が起きる前のバックアップ（最新の `db_backup_*`、`db_manual_*`、`db_safety_*` ファイル）を選び、`~/.cc-switch/cc-switch.db` として **コピー** します。
5. CC Switch を起動します。古いバージョンのバックアップは自動的にアップグレードされます（事前に `db_premigration_` バックアップを作成）。新しいバージョンの CC Switch で作られたバックアップは拒否されるので、先にアプリを更新してください。
6. プロバイダを一度切り替えて、各ツールのライブ設定ファイルを復元後のデータで書き直します。

エラーが `settings.json` を示している場合は、上の「settings.json の破損」を参照してください。スキルについては、アンインストール時のコピーが `skill-backups/` にあり、スキルパネルから復元できます。データ以外の起動トラブルは [5.6 トラブルシューティング](./5.6-troubleshooting.md) を参照してください。

## Claude Code の設定

### 設定ディレクトリ

デフォルト：`~/.claude/`

### 主要ファイル

```
~/.claude/
├── settings.json     # メイン設定ファイル
├── CLAUDE.md         # システムプロンプト
└── skills/           # スキルディレクトリ
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxx",
    "ANTHROPIC_BASE_URL": "https://api.example.com",
    "ANTHROPIC_MODEL": "example-model"
  },
  "permissions": {
    "allow": ["Bash(git status)"]
  }
}
```

| フィールド | 説明 |
|------|------|
| `env.ANTHROPIC_AUTH_TOKEN` | API キー（CC Switch はほとんどのプロバイダーでこの変数を書き込みます） |
| `env.ANTHROPIC_API_KEY` | API キー、一部のプロバイダーが使う代替変数 |
| `env.ANTHROPIC_BASE_URL` | API エンドポイント（公式 API では省略） |
| `env.ANTHROPIC_MODEL`、`env.ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL` | モデルの上書き |
| `permissions.allow` / `permissions.deny` | Claude Code のツール権限ルール（文字列のリスト） |

### MCP 設定

MCP サーバーの設定は `~/.claude.json` にあります：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Codex の設定

### 設定ディレクトリ

デフォルト：`~/.codex/`

### 主要ファイル

```
~/.codex/
├── auth.json         # 認証設定
├── config.toml       # メイン設定 + MCP
└── AGENTS.md         # システムプロンプト
```

### auth.json

```json
{
  "OPENAI_API_KEY": "sk-xxx"
}
```

### config.toml

CC Switch はサードパーティプロバイダーを `model_provider = "custom"` と `[model_providers.custom]` テーブルの形で書き込みます：

```toml
model_provider = "custom"
model = "gpt-5.5"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.custom]
name = "My Provider"
base_url = "https://api.example.com/v1"
wire_api = "responses"
requires_openai_auth = true

# MCP servers
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

## Hermes の設定

### 設定ディレクトリ

デフォルト：`~/.hermes/`

### 主要ファイル

```
~/.hermes/
├── config.yaml       # メイン設定、プロバイダー、MCP 設定

├── SOUL.md           # Profile identity/persona
```

### config.yaml

Hermes は YAML 設定を使用します。CC Switch は MCP サーバーを `mcp_servers` に書き込み、編集可能なプロバイダーエントリを `custom_providers` に書き込み、Hermes の `providers` dict にある読み取り専用エントリを読み取り、プロバイダー切り替え時に `model.provider` / `model.default` を更新します。

## OpenClaw の設定

### 設定ディレクトリ

デフォルト：`~/.openclaw/`

### 主要ファイル

```
~/.openclaw/
├── openclaw.json     # メイン設定ファイル（JSON5 形式）
└── skills/           # スキルディレクトリ
    └── ...
```

### openclaw.json

OpenClaw は JSON5 形式の設定ファイルを使用し、主に以下のセクションを含みます：

```json5
{
  // モデルプロバイダー設定
  models: {
    mode: "merge",
    providers: {
      "custom-provider": {
        baseUrl: "https://api.example.com/v1",
        apiKey: "your-api-key",
        api: "openai-completions",
        models: [{ id: "model-id", name: "Model Name" }]
      }
    }
  },
  // 環境変数
  env: {
    ANTHROPIC_API_KEY: "sk-..."
  },
  // Agent デフォルト設定
  agents: {
    defaults: {
      model: {
        primary: "provider/model"
      },
      workspace: "~/.openclaw/workspace"
    }
  },
  // ツール設定
  tools: {}
}
```

| フィールド | 説明 |
|------|------|
| `models.providers` | プロバイダー設定（CC Switch の「プロバイダー」にマッピング） |
| `env` | 環境変数設定 |
| `agents.defaults` | Agent デフォルトモデル設定 |
| `tools` | ツール設定 |
| `agents.defaults.workspace` | ワークスペースディレクトリパス |

## 設定の優先順位

CC Switch が設定を変更する際の優先順位：

1. **CC Switch データベース** - 単一事実源 (SSOT)
2. **Live 設定ファイル** - プロバイダー切り替え時に書き込み
3. **バックフィル機能** - 現在のプロバイダーの編集時に Live ファイルから読み取り

## 手動での設定編集

### 手動編集可能なもの

- CLI ツールの設定ファイル（CC Switch がバックフィルする）
- CC Switch の `settings.json`（ただし CC Switch を終了している間のみ。設定変更時にアプリがファイルを書き直します）。未知のキーは無視されます

### 手動編集を推奨しないもの

- `cc-switch.db` データベースファイル
- バックアップファイル

### 編集後の同期

CLI ツールの設定を手動で編集した場合：

1. CC Switch を開く
2. 対応するプロバイダーを編集
3. 手動変更の内容がバックフィルされていることを確認
4. 保存してデータベースに同期

## 設定の移行

### 旧バージョンからの移行

CC Switch v3.7.0 で JSON ファイルから SQLite に移行しました：

- 初回起動時に自動的に移行
- 移行成功後に通知を表示
- 旧設定ファイルはバックアップとして保持

### デバイス間の移行

1. 移行元のデバイスで設定をエクスポート
2. 移行先のデバイスで設定をインポート
3. またはクラウド同期機能を使用

## 設定のバックアップに関するアドバイス

### 定期的なバックアップ

定期的に設定をエクスポートすることを推奨します：

1. 設定 → 詳細 → データ管理
2. 「エクスポート」をクリック
3. 安全な場所に保存

### バックアップに含まれる内容

エクスポートファイルには以下が含まれます：

- すべてのプロバイダー設定
- MCP サーバー設定
- Prompts プリセット
- アプリ設定

### 含まれない内容

- 使用量ログ（データ量が大きいため）
- デバイスレベルの設定（デバイス間の移動に適さないため）
