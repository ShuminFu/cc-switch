# 5.6 トラブルシューティング

OS ごとに、症状・対処法・バグ報告に添付するファイルをまとめています。機能に関する質問は [5.2 よくある質問](./5.2-questions.md) を参照してください。

## ログとクラッシュログ

CC Switch のファイルはすべてデータディレクトリ（既定は `~/.cc-switch`、または 設定 → 詳細 → 設定ディレクトリ で指定した場所）に置かれます。

| ファイル | macOS / Linux | Windows | 内容 |
| --- | --- | --- | --- |
| アプリログ | `~/.cc-switch/logs/cc-switch.log`（ローテーション） | `%USERPROFILE%\.cc-switch\logs\cc-switch.log` | ローカルプロキシ（リクエスト、フェイルオーバー、サーキットブレーカー）を含むアプリの動作記録。ログレベルは 設定 → 詳細 → ログ設定 で変更 |
| クラッシュログ | `~/.cc-switch/crash.log` | `%USERPROFILE%\.cc-switch\crash.log` | クラッシュ時の panic メッセージとバックトレース |
| プロキシのリクエスト記録 | `cc-switch.db` 内 | `cc-switch.db` 内 | リクエストごとのステータス、レイテンシ、トークン数。使用量ダッシュボードで確認（[4.4](../4-proxy/4.4-usage.md)） |

**公開 Issue にログを添付する前に**、API キー、トークン、公開したくない Base URL を削除してください。既定の `info` レベルではシークレットはマスクされますが、`debug`/`trace` ログ、プロバイダ設定（`settings.json`、`auth.json`、`.env`）、スクリーンショットには含まれることがあります。

### ターミナルから起動して起動エラーを確認する

ウィンドウが開く前のエラーはターミナルに出力されます。

- **macOS**: `/Applications/CC\ Switch.app/Contents/MacOS/cc-switch`
- **Linux**: `cc-switch`（deb/rpm）または `./CC-Switch-*.AppImage`
- **Windows**（PowerShell）: `& "$env:LOCALAPPDATA\Programs\CC Switch\cc-switch.exe"`

## Windows

| 症状 | 対処法 |
| --- | --- |
| 「Windows によって PC が保護されました」（SmartScreen） | ビルドに Authenticode 署名がありません。「詳細情報」→「実行」を選択。事前に `SHA256SUMS` で検証できます（[SECURITY.md](../../../../SECURITY.md#verifying-a-download)） |
| インストール後に起動しない | [WebView2 ランタイム](https://developer.microsoft.com/microsoft-edge/webview2/)をインストール。ウイルス対策ソフトで CC Switch を許可 |
| ARM PC で別のビルドを使っている | `-Windows-arm64.msi` / `-arm64-Portable.zip` を使用 |
| ポータブル版でアプリ内アップデートができない | 新しい `-Portable.zip` をダウンロードして `cc-switch.exe` を置き換え（同じフォルダの `portable.ini` は残す）。データは `%USERPROFILE%\.cc-switch` に残ります |
| プロキシが起動しない: ポート使用中 | 別のプログラム（または別の CC Switch）がポート 15721 を使用中。プロキシパネルでポートを変更するか、`netstat -ano | findstr 15721` でプロセスを特定 |
| アップデートに失敗する | Releases ページから MSI をダウンロードして上書きインストール。`%USERPROFILE%\.cc-switch` のデータは保持されます |

## macOS

| 症状 | 対処法 |
| --- | --- |
| 「開発元を確認できないため開けません」 | 通常は発生しません（署名・公証済み）。公式の Releases ページまたは Homebrew から入手したか確認して再試行 |
| トレイアイコンが表示されない | メニューバーのアイコンが多すぎます。いくつか非表示にするか、メニューバー管理ツールを使用 |
| アプリが起動しない | 上記の方法でターミナルから起動し、`~/.cc-switch/crash.log` を確認 |
| プロキシが起動しない: ポート使用中 | `lsof -nP -iTCP:15721 -sTCP:LISTEN` でプロセスを確認し、ポートを変更するかプロセスを終了 |

## Linux

| 症状 | 対処法 |
| --- | --- |
| AppImage が起動しない | `chmod +x CC-Switch-*.AppImage`。FUSE 2 がない環境では `./CC-Switch-*.AppImage --appimage-extract-and-run` |
| `.deb`/`.rpm` で `libwebkit2gtk-4.1` や glibc シンボルが見つからない | パッケージには glibc 2.35 以上と WebKitGTK 4.1 が必要です（Ubuntu 22.04+、Debian 12+、Fedora 36+）。古い環境では AppImage を使用 |
| クリックが反応しない / リサイズで黒画面（Wayland + NVIDIA） | `CC_SWITCH_GDK_BACKEND=wayland` で起動（sway/Hyprland では `=x11`）。[5.2](./5.2-questions.md) を参照 |
| ウィンドウが真っ白・ちらつく | `WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 cc-switch` を試す（アプリは既定でこの 2 つを設定済み） |
| トレイアイコンが表示されない（GNOME） | 拡張機能「AppIndicator and KStatusNotifierItem Support」をインストール |
| `ccswitch://` リンクでアプリが開かない | `xdg-mime default <cc-switch の desktop ファイル> x-scheme-handler/ccswitch` を実行（desktop ファイル名は `/usr/share/applications/` を参照） |
| Flatpak: ツールが「未インストール」、ターミナルが開かない | サンドボックスの既知の制限です。[`flatpak/README.md`](../../../../flatpak/README.md) を参照 |
| プロキシが起動しない: ポート使用中 | `ss -ltnp | grep 15721` でプロセスを確認し、ポートを変更するかプロセスを終了 |

## 全プラットフォーム共通

| 症状 | 対処法 |
| --- | --- |
| 設定ファイルを読み込めないというエラーが出て終了する | `~/.cc-switch` 内のファイルが破損しています。[5.1 手動での復元](./5.1-config-files.md#アプリが起動しないときの手動復元)を参照 |
| 切り替えが反映されない | CLI ツールを再起動。環境変数による上書きを確認（[5.4](./5.4-env-conflict.md)） |
| フェイルオーバーが発生しない / 頻繁すぎる | どのエラーが対象になるかは [4.6 プロキシの動作仕様](../4-proxy/4.6-semantics.md) を参照 |
| CC Switch がクラッシュ・強制終了した後もツールが `127.0.0.1:15721` を向いている | CC Switch を再起動してください。起動時に取り残されたテイクオーバーを検出し、バックアップから元の設定を復元します |

## バグ報告

[バグ報告フォーム](https://github.com/farion1231/cc-switch/issues/new?template=bug_report.yml)を使用してください。バージョン、OS とアーキテクチャ、インストール方法、表示言語を記入し、アプリログ（クラッシュ時は `crash.log` も）をシークレットを削除したうえで添付してください。
