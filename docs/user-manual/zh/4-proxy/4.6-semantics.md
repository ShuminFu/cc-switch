# 4.6 代理行为说明：哪些情况算失败

前面几页介绍的是界面操作，本页说明代理遵循的规则，帮助你预判它何时切换供应商、何时放弃、以及会修改磁盘上的哪些文件。以下规则取自 `src-tauri/src/proxy/`（v3.17.0 及以后）。

## 会尝试哪些供应商、按什么顺序

| 该应用的自动故障转移 | 尝试的供应商 |
| --- | --- |
| **关闭** | 只使用当前供应商。不检查熔断器，下文的分阶段超时也不生效（仅有 600 秒的响应头等待上限），错误直接返回给工具 |
| **开启** | 按 **故障转移队列的顺序**（P1 → P2 → …）依次尝试，跳过熔断器处于打开状态的供应商。除非当前供应商就是 P1，否则不会优先尝试它 |

每个请求最多尝试 `重试次数 + 1` 个供应商（默认重试 3 次，即最多 4 个）。队列中所有供应商都已熔断时，请求以"所有供应商均已熔断"（`FO-004`）失败；队列为空时以"未配置供应商"（`FO-005`）失败。

## 哪些错误会切换到下一个供应商

| 一次尝试的结果 | 切换下一个？ | 计入熔断器？ |
| --- | --- | --- |
| 连接被拒绝 / DNS / TLS 错误 | 是 | 是 |
| 连接超时（10 秒） | 是 | 是 |
| 流式：在 **首字节超时** 内没有收到响应头和第一个数据块 | 是 | 是 |
| 流式：收到第一个数据块后，**空闲超时** 内没有新数据（尚未向工具发送任何内容时） | 是 | 是 |
| 非流式：在 **非流式超时** 内没有收到完整响应 | 是 | 是 |
| HTTP **401、403、404、408、409、429、451** 以及下方未列出的其他 4xx | 是 | 是 |
| HTTP **5xx**（501 除外） | 是 | 是 |
| HTTP 2xx 但响应体是错误信封，或流以错误事件开头 | 是（失败即关闭，而不是返回空回复） | 是 |
| HTTP **400、405、406、413、414、415、422**（请求本身有误） | **否**，直接返回给工具 | 否 |
| HTTP **501**（上游没有实现该接口） | **否** | 否 |
| 工具取消了请求 | 否 | 否 |
| Codex 官方（ChatGPT）账号返回 401 / 403 | **否**：登录属于 Codex，切换供应商会在不知不觉中把对话转移到别处 | 否 |

流式响应的第一批数据一旦发送给工具，代理就无法再切换供应商：之后的失败会以错误结束该响应。

部分内置修复（thinking 签名整流器、thinking 预算整流器）会先用修正后的请求对 **同一** 供应商重试一次，然后才按上表归类失败。

## 超时

在代理面板中按应用配置，`0` 表示关闭该阶段。默认值：

| 超时 | 默认值 | 计时起点 |
| --- | --- | --- |
| 连接 | 10 秒（固定） | 建立 TCP/TLS 连接 |
| 流式首字节 | 60 秒 | 从发送请求到收到第一个数据块（含响应头） |
| 流式空闲 | 120 秒 | 两个数据块之间 |
| 非流式 | 600 秒 | 从发送请求到收到完整响应体 |

关闭故障转移时，只有连接超时和 600 秒的响应头上限生效。

## 熔断器

每个应用的每个供应商都有独立的熔断器（`app:provider`）。默认值（可在代理设置中修改）：

| 状态 | 含义 | 何时离开该状态 |
| --- | --- | --- |
| **关闭** | 正常放行 | **连续 4 次失败**，或 60 秒内最近 **10** 次请求的错误率 ≥ **60%** → 打开 |
| **打开** | 跳过该供应商 | **60 秒** 后 → 半开 |
| **半开** | 每次只放行一个探测请求 | **成功 2 次** → 关闭；失败 → 重新打开 |

只有上表中"计入熔断器"的结果会改变熔断状态。无效请求（400、422 等）和取消不会，因此一个有问题的客户端不会让所有熔断器都打开。

## 接管会修改磁盘上的什么

为某个应用开启接管（4.2）时：

1. 该应用当前的 Live 配置会保存到数据库（`proxy_live_backup`）。
2. Live 配置被改写为指向代理（例如 Claude 的 `settings.json` 中 `ANTHROPIC_BASE_URL` = `http://127.0.0.1:15721`），真实 API 密钥被替换为占位符 `PROXY_MANAGED`，由代理在转发时加上真实密钥。
3. 关闭接管（或停止代理）时，保存的副本会被写回。
4. 如果 CC Switch 在接管期间崩溃或被强制结束，下次启动时会检测到残留的占位符或备份，并自动恢复原始配置。

接管开启期间切换供应商，改变的是代理转发的目标；工具自己的配置文件始终指向代理。

## 查看日志

上述每个决定都会带编码记录在 `~/.cc-switch/logs/cc-switch.log` 中，例如 `FO-004`（所有供应商均已熔断）。日志位置见 [5.6 故障排查](../5-faq/5.6-troubleshooting.md)，队列与健康状态界面见 [4.3 故障转移](./4.3-failover.md)。
