# 2.7 Grok Build

## 概述

[Grok Build](https://www.npmjs.com/package/@xai-official/grok) 是 xAI 推出的编程 CLI。从 v3.17.0 起，CC Switch 将它作为与 Claude Code、Codex、Gemini CLI 并列的一级应用进行管理：

| 功能 | 支持情况 |
|------|----------|
| 供应商切换 | 支持，写入 `~/.grok/config.toml` |
| MCP 服务器 | 支持，保存在 `config.toml` 的 `[mcp_servers]` 表中 |
| Skills | 支持，安装到 `~/.grok/skills/` |
| 提示词 | 支持，写入 `~/.grok/AGENTS.md` |
| 会话管理 | 支持，读取 `~/.grok/sessions/` 与 `~/.grok/archived_sessions/` |
| 本地代理接管与故障转移 | 支持 |
| CLI 安装 / 升级 | 支持，在 设置 → 关于 中操作（`npm i -g @xai-official/grok@latest`） |
| 项目（Profiles） | 不支持（项目目前覆盖 Claude Code、Claude Desktop 与 Codex） |

如果应用切换器中没有 Grok Build，请在 **设置 → 通用 → 主页面显示** 中打开它。

## 配置文件

Grok Build 只读取一个 TOML 文件。CC Switch 负责其中的模型选择部分；MCP 服务器也保存在同一文件中，由 MCP 页面管理。

```toml
[models]
default = "grok-4.5"            # Grok Build 使用的客户端模型配置名

[model."grok-4.5"]
model = "grok-4.5"              # 发送给供应商的模型名
name = "My Provider"
base_url = "https://api.example.com/v1"
api_key = "sk-..."              # 或 env_key = "MY_PROVIDER_API_KEY"
api_backend = "responses"       # responses / chat_completions / messages
context_window = 500000
```

保存供应商前，CC Switch 会校验该文件：`[models].default` 指向的表必须存在，且包含 `model`、`base_url`、`name`、`api_backend`、正整数 `context_window`，以及 `api_key` 或 `env_key` 之一。

配置目录可在 **设置 → 高级 → 配置目录 → Grok Build 配置目录** 中修改（对应 `settings.json` 中的 `grokConfigDir`）。

## 添加供应商

1. 在应用切换器中选择 **Grok Build**
2. 点击右上角的 **+**
3. 选择一个预设，或选择 **自定义**

Grok Build 复用 Codex 的第三方预设（不提供 OpenAI 官方条目），大多数 OpenAI 兼容网关一键即可添加。

### 表单字段

| 字段 | `config.toml` 键 | 说明 |
|------|------------------|------|
| 名称 | `name` | 显示名称，同时写入模型表 |
| API Key | `api_key` | 直接写入文件。如在原始编辑器中使用 `env_key`，可留空 |
| 端点 | `base_url` | 供应商 Base URL |
| 客户端模型配置 | `[models].default` | Grok Build 选择的配置名，默认 `grok-4.5` |
| 模型 | `model` | 发送到上游的模型，默认与配置名相同 |
| API 后端 | `api_backend` | `responses`（默认）、`chat_completions` 或 `messages`（Anthropic Messages） |
| 上下文窗口 | `context_window` | 正整数，默认 `500000` |

表单下方的 **config.toml** 编辑器显示完整文档，两处的修改会保持同步；TOML 无效时无法保存。

## 切换供应商

可以在供应商卡片、主界面或托盘菜单中切换。CC Switch 会重写 `~/.grok/config.toml` 中的模型表，并保留你的 `[mcp_servers]` 条目。切换后会提示 **重启 Grok Build** 以加载新供应商。

## 配合本地代理使用

Grok Build 可以像 Claude Code、Codex、Gemini CLI 一样被本地代理接管：

- 在代理面板中打开 **Grok Build** 的接管开关（见 [4.2 应用路由](../4-proxy/4.2-routing.md)）
- 接管期间，`base_url` 指向 `http://127.0.0.1:<端口>/grokbuild/v1`，请求经由当前供应商转发
- 故障转移队列、熔断器与用量统计与其他应用一致（见 [4.3 故障转移](../4-proxy/4.3-failover.md)）

## 常见问题

| 问题 | 解决方法 |
|------|----------|
| 提示 "Grok Build 配置缺少 [models]" | 原始 `config.toml` 中没有 `[models]` 表。重新填写表单字段，或手动添加 `[models] default = "..."` |
| 提示 "缺少有效的 api_key 或 env_key 字段" | 填写 API Key，或将 `env_key` 设为保存密钥的环境变量名 |
| 切换后没有生效 | 重启 Grok Build，它只在启动时读取 `config.toml` |
| Grok Build 中看不到 MCP 服务器 | 仅当 `~/.grok/` 存在时才会同步 MCP。先启动一次 Grok Build，再在 MCP 页面为 Grok Build 打开该服务器 |
