# 5.6 故障排查

按操作系统整理：症状、解决方法，以及提交 Bug 时需要附上哪些文件。功能相关问题请看 [5.2 常见问题](./5.2-questions.md)。

## 日志与崩溃日志

CC Switch 的所有文件都在数据目录下（默认 `~/.cc-switch`，或你在 设置 → 高级 → 配置目录 中指定的目录）。

| 文件 | macOS / Linux | Windows | 内容 |
| --- | --- | --- | --- |
| 应用日志 | `~/.cc-switch/logs/cc-switch.log`（滚动） | `%USERPROFILE%\.cc-switch\logs\cc-switch.log` | 应用的全部运行记录，包括本地代理（请求、故障转移、熔断）。日志级别在 设置 → 高级 → 日志配置 中设置 |
| 崩溃日志 | `~/.cc-switch/crash.log` | `%USERPROFILE%\.cc-switch\crash.log` | 应用崩溃时的 panic 信息与调用栈 |
| 代理请求记录 | 位于 `cc-switch.db` 内 | 位于 `cc-switch.db` 内 | 每个请求的状态、延迟与 Token 数；在用量面板中查看（见 [4.4](../4-proxy/4.4-usage.md)） |

**把日志附到公开 Issue 之前**，请删除 API 密钥、令牌以及不想公开的 Base URL。默认 `info` 级别下密钥会被脱敏，但 `debug`/`trace` 日志、供应商配置（`settings.json`、`auth.json`、`.env`）和截图中可能包含它们。

### 在终端中运行以查看启动错误

窗口出现之前发生的错误会打印到终端：

- **macOS**：`/Applications/CC\ Switch.app/Contents/MacOS/cc-switch`
- **Linux**：`cc-switch`（deb/rpm）或 `./CC-Switch-*.AppImage`
- **Windows**（PowerShell）：`& "$env:LOCALAPPDATA\Programs\CC Switch\cc-switch.exe"`

## Windows

| 症状 | 解决方法 |
| --- | --- |
| 提示"Windows 已保护你的电脑"（SmartScreen） | 安装包尚无 Authenticode 签名。点击"更多信息"→"仍要运行"。运行前可用 `SHA256SUMS` 校验文件（[SECURITY.md](../../../../SECURITY.md#verifying-a-download)） |
| 安装后无法启动 | 安装 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)；在杀毒软件中放行 CC Switch |
| ARM 电脑用错了版本 | 使用 `-Windows-arm64.msi` / `-arm64-Portable.zip` |
| 绿色版无法应用内更新 | 下载新的 `-Portable.zip` 替换 `cc-switch.exe`（保留同目录下的 `portable.ini`）；数据保存在 `%USERPROFILE%\.cc-switch`，不受影响 |
| 代理无法启动：端口被占用 | 其他程序（或另一个 CC Switch）占用了 15721 端口。在代理面板中更换端口，或用 `netstat -ano | findstr 15721` 找到对应进程 |
| 更新失败 | 从 Releases 页面下载 MSI 覆盖安装；`%USERPROFILE%\.cc-switch` 中的数据会保留 |

## macOS

| 症状 | 解决方法 |
| --- | --- |
| 提示"无法打开，因为无法验证开发者" | 正常不会出现：安装包已签名并公证。请确认是从官方 Releases 页面或 Homebrew 下载的，然后重试 |
| 托盘图标不显示 | 菜单栏图标过多：隐藏一些，或使用菜单栏管理工具 |
| 应用无法启动 | 按上文在终端中运行，并查看 `~/.cc-switch/crash.log` |
| 代理无法启动：端口被占用 | `lsof -nP -iTCP:15721 -sTCP:LISTEN` 查看占用进程；更换端口或结束该进程 |

## Linux

| 症状 | 解决方法 |
| --- | --- |
| AppImage 无法启动 | `chmod +x CC-Switch-*.AppImage`；系统没有 FUSE 2 时运行 `./CC-Switch-*.AppImage --appimage-extract-and-run` |
| `.deb`/`.rpm` 提示缺少 `libwebkit2gtk-4.1` 或 glibc 符号 | 安装包需要 glibc 2.35+ 和 WebKitGTK 4.1（Ubuntu 22.04+、Debian 12+、Fedora 36+）。更旧的系统请使用 AppImage |
| 点击无响应 / 调整大小时黑屏（Wayland + NVIDIA） | 使用 `CC_SWITCH_GDK_BACKEND=wayland` 启动（sway/Hyprland 上改为 `=x11`）。见 [5.2](./5.2-questions.md) |
| 窗口空白或闪烁 | 尝试 `WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 cc-switch`（应用默认已设置这两项） |
| 滚动卡顿或 CPU 占用高（较新的 WebKitGTK，GPU 正常） | 以 `CC_SWITCH_WEBKIT_GPU=1 cc-switch` 启动，保留 WebKitGTK 的 GPU 合成与 DMA-BUF 渲染（应用默认关闭这两项）；若窗口变空白请去掉该变量 |
| 托盘图标不显示（GNOME） | 安装 "AppIndicator and KStatusNotifierItem Support" 扩展 |
| `ccswitch://` 链接无法打开应用 | 运行 `xdg-mime default <cc-switch 的 desktop 文件> x-scheme-handler/ccswitch`（desktop 文件名见 `/usr/share/applications/`） |
| Flatpak：工具显示"未安装"、终端打不开 | 沙盒的已知限制，见 [`flatpak/README.md`](../../../../flatpak/README.md) |
| 代理无法启动：端口被占用 | `ss -ltnp | grep 15721` 查看占用进程；更换端口或结束该进程 |

## 所有平台

| 症状 | 解决方法 |
| --- | --- |
| 应用提示无法读取配置文件并退出 | `~/.cc-switch` 中的文件已损坏。见 [5.1 手动恢复](./5.1-config-files.md#应用无法启动时手动恢复) |
| 切换后不生效 | 重启对应的 CLI 工具；检查是否有环境变量覆盖（[5.4](./5.4-env-conflict.md)） |
| 故障转移不触发 / 触发过于频繁 | 哪些错误会计入，见 [4.6 代理行为说明](../4-proxy/4.6-semantics.md) |
| CC Switch 崩溃或被强制结束后，工具仍指向 `127.0.0.1:15721` | 重新启动 CC Switch：启动时会检测接管残留，并从备份恢复原始的 Live 配置 |

## 提交 Bug

请使用 [Bug 报告表单](https://github.com/farion1231/cc-switch/issues/new?template=bug_report.yml)。表单会询问版本、系统与架构、安装方式和界面语言；请附上应用日志，崩溃时附上 `crash.log`，并先删除其中的密钥。
