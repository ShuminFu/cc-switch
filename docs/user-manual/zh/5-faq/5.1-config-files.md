# 5.1 配置文件说明

## CC Switch 数据存储

### 存储目录

默认位置：`~/.cc-switch/`

可在设置中更改位置（例如放到云同步文件夹中），所选路径记录在 Tauri 的 `app_paths.json` 存储里。`settings.json` 始终保留在 `~/.cc-switch/`。

### 目录结构

```
~/.cc-switch/
├── cc-switch.db      # SQLite 数据库（SSOT）
├── settings.json     # 设备级设置
├── skills/           # 技能 SSOT 目录
├── skill-backups/    # 技能备份（卸载时创建）
├── backups/          # 数据库备份（db_*.db）
│   └── <app>/        # CC Switch 覆盖 live 配置文件前保存的副本
└── logs/             # cc-switch.log（应用日志）与 crash.log
```

### 数据库内容

`cc-switch.db` 是 SQLite 数据库，存储：

| 表 | 内容 |
|-----|------|
| providers | 供应商配置（按应用） |
| provider_endpoints | 供应商端点候选列表 |
| mcp_servers | MCP 服务器配置及各应用开关 |
| prompts | 提示词预设 |
| skills | 已安装技能及各应用开关 |
| skill_repos | 技能仓库列表 |
| profiles | 项目配置（供应商 / MCP / 技能 / 提示词状态的命名快照） |
| settings | 随数据库同步的键值状态（通用配置片段、当前项目等） |
| proxy_config | 本地代理、故障转移与熔断设置（每个代理应用一行） |
| proxy_live_backup | 代理接管期间各应用 Live 配置的备份 |
| provider_health | 供应商健康 / 故障转移状态 |
| proxy_request_logs | 逐请求用量日志（代理与会话同步） |
| usage_daily_rollups | 明细日志清理后保留的每日用量汇总 |
| session_log_sync | 导入用量统计的 CLI 会话日志读取进度 |
| stream_check_logs | 供应商流式健康检查结果 |
| model_pricing | 用于计算费用的模型定价 |

### 设备设置

`settings.json` 存储**不会**跨设备同步的设备级设置。键名为 camelCase，与 `src-tauri/src/settings.rs` 中的 `AppSettings` 一致；未设置的键不会写入文件。典型内容：

```json
{
  "showInTray": true,
  "minimizeToTrayOnClose": true,
  "useAppWindowControls": false,
  "launchOnStartup": false,
  "silentStartup": false,
  "language": "en",
  "visibleApps": {
    "claude": true,
    "claude-desktop": true,
    "codex": true,
    "gemini": true,
    "grokbuild": true,
    "opencode": true,
    "openclaw": true,
    "hermes": false
  },
  "enableClaudePluginIntegration": false,
  "skipClaudeOnboarding": false,
  "enableLocalProxy": false,
  "enableFailoverToggle": false,
  "showProfileSwitcher": true,
  "preserveCodexOfficialAuthOnSwitch": false,
  "unifyCodexSessionHistory": false,
  "claudeConfigDir": "/custom/path/.claude",
  "currentProviderClaude": "my-provider-1730000000000",
  "skillSyncMethod": "auto",
  "skillStorageLocation": "cc_switch",
  "backupIntervalHours": 24,
  "backupRetainCount": 10,
  "preferredTerminal": "iterm2"
}
```

主要键：

| 键 | 默认值 | 含义 |
|----|--------|------|
| `showInTray` / `minimizeToTrayOnClose` | `true` / `true` | 托盘图标；点击关闭时隐藏到托盘而非退出 |
| `useAppWindowControls` | `false` | 使用应用自带的标题栏按钮 |
| `launchOnStartup` / `silentStartup` | `false` | 开机自启；启动时仅在托盘运行 |
| `language` | 跟随系统 | `en`、`zh`、`zh-TW` 或 `ja` |
| `visibleApps` | 除 Hermes 外全部 | 主页面显示哪些应用 |
| `enableClaudePluginIntegration` | `false` | 同时切换 Claude Code VS Code 插件 |
| `skipClaudeOnboarding` | `false` | 跳过 Claude Code 首次运行确认 |
| `enableLocalProxy` / `enableFailoverToggle` | `false` | 在主页面显示本地代理与故障转移开关 |
| `showProfileSwitcher` | `true` | 在标题栏显示项目切换器 |
| `preserveCodexOfficialAuthOnSwitch` / `unifyCodexSessionHistory` | `false` | Codex 官方登录与会话历史选项 |
| `claudeConfigDir`、`codexConfigDir`、`geminiConfigDir`、`grokConfigDir`、`opencodeConfigDir`、`openclawConfigDir`、`hermesConfigDir` | 未设置 | 覆盖各工具的配置目录 |
| `currentProvider<App>` | 未设置 | 本设备上各应用的当前供应商 ID（优先于数据库） |
| `skillSyncMethod` / `skillStorageLocation` | `auto` / `cc_switch` | 技能同步方式（`auto`、`symlink`、`copy`）与存储位置（`cc_switch` 或 `unified` = `~/.agents/skills/`） |
| `webdavSync` / `s3Sync` | 未设置 | 云同步设置（含凭据） |
| `backupIntervalHours` / `backupRetainCount` | `24` / `10` | 数据库自动备份间隔（`0` 为关闭）与保留份数 |
| `preferredTerminal` | 系统默认 | 打开会话使用的终端 |

`proxyConfirmed`、`usageConfirmed`、`failoverConfirmed`、`firstRunNoticeConfirmed`、`commonConfigConfirmed` 记录已关闭的首次提示；`localMigrations` 记录本设备已执行的一次性迁移。

界面主题**不在** `settings.json` 中，而是保存在应用的浏览器存储里（`localStorage` 键 `cc-switch-theme`）。

### 自动备份

`backups/` 目录存储自动备份：

- 定期创建（每 `backupIntervalHours` 小时，默认 24 小时），并在数据库迁移和 SQL 导入前创建
- 文件名以备份类型开头：`db_backup_`（定时）、`db_manual_`（立即备份）、`db_safety_`（导入、同步下载或恢复前）、`db_premigration_`（数据库结构升级前）
- 每种类型各自保留最近 `backupRetainCount` 个文件（默认 10 个）；手动备份和重命名过的备份永远不会被自动删除
- 可在设置中恢复、重命名或删除（见 [1.5 个性化配置](../1-getting-started/1.5-settings.md)）

### Live 配置文件备份

CC Switch 在覆盖工具的 live 配置文件之前（例如切换供应商时），会把当前文件复制到 `~/.cc-switch/backups/<app>/<文件名>_<时间戳>.<扩展名>`。涵盖 Claude 的 `settings.json`、Codex 的 `auth.json` 与 `config.toml`、Gemini 的 `.env` 与 `settings.json`。文件与上次副本相同时不会重复备份，保留数量遵循 `backupRetainCount`。

如果 live 文件无法解析（例如手动编辑后有语法错误的 Gemini `settings.json`），切换会报错并指出该文件，而不会用新文件替换它。包含密钥的文件（Claude `settings.json`、Codex `auth.json` / `config.toml`）创建时仅当前用户可读。

### settings.json 损坏

如果启动时 `~/.cc-switch/settings.json` 无法解析，CC Switch 会将其重命名为 `settings.json.corrupt-<时间戳>`，记录错误日志，并以默认设置启动。原文件会被保留，你可以修复后再复制回来。

### 应用无法启动时手动恢复

应用能正常运行时，请使用 设置 → 高级 → 备份与恢复 中的 **恢复** 按钮。如果数据库损坏导致 CC Switch 无法启动，可以手动恢复备份：

1. 完全退出 CC Switch（托盘图标 → 退出；确认没有残留的 `cc-switch` 进程）。
2. 打开数据目录：`~/.cc-switch`（Windows：`%USERPROFILE%\.cc-switch`）。
3. 把当前数据库移开并保留，以备之后需要：将 `cc-switch.db` 重命名为 `cc-switch.db.broken`，如果存在 `cc-switch.db-wal` 和 `cc-switch.db-shm`，也同样重命名。
4. 在 `backups/` 中选择一个出问题之前的备份（最新的 `db_backup_*`、`db_manual_*` 或 `db_safety_*` 文件），把它 **复制** 为 `~/.cc-switch/cc-switch.db`。
5. 启动 CC Switch。旧版本的备份会自动升级（升级前会先生成 `db_premigration_` 备份）；来自更新版本 CC Switch 的备份会被拒绝，请先升级应用。
6. 重新切换一次供应商，让各工具的 Live 配置文件按恢复后的数据重写。

如果报错提到的是 `settings.json`，请看上文"settings.json 损坏"。技能方面，`skill-backups/` 目录保存了卸载技能时的副本，可在技能面板中恢复。与数据无关的启动问题见 [5.6 故障排查](./5.6-troubleshooting.md)。

## Claude Code 配置

### 配置目录

默认：`~/.claude/`

### 主要文件

```
~/.claude/
├── settings.json     # 主配置文件
├── CLAUDE.md         # 系统提示词
└── skills/           # 技能目录
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxx",
    "ANTHROPIC_BASE_URL": "https://api.example.com",
    "ANTHROPIC_MODEL": "example-model"
  },
  "permissions": {
    "allow": ["Bash(git status)"]
  }
}
```

| 字段 | 说明 |
|------|------|
| `env.ANTHROPIC_AUTH_TOKEN` | API 密钥（CC Switch 为大多数供应商写入此变量） |
| `env.ANTHROPIC_API_KEY` | API 密钥，部分供应商使用的替代变量 |
| `env.ANTHROPIC_BASE_URL` | API 端点（官方 API 可省略） |
| `env.ANTHROPIC_MODEL`、`env.ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL` | 模型覆盖 |
| `permissions.allow` / `permissions.deny` | Claude Code 工具权限规则（字符串列表） |

### MCP 配置

MCP 服务器配置在 `~/.claude.json`：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Codex 配置

### 配置目录

默认：`~/.codex/`

### 主要文件

```
~/.codex/
├── auth.json         # 认证配置
├── config.toml       # 主配置 + MCP

```

### auth.json

```json
{
  "OPENAI_API_KEY": "sk-xxx"
}
```

### config.toml

CC Switch 以 `model_provider = "custom"` 加 `[model_providers.custom]` 表的形式写入第三方供应商：

```toml
model_provider = "custom"
model = "gpt-5.5"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.custom]
name = "My Provider"
base_url = "https://api.example.com/v1"
wire_api = "responses"
requires_openai_auth = true

# MCP servers
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

## Grok Build 配置

### 配置目录

默认：`~/.grok/`（可通过 `grokConfigDir` 修改）

### 关键文件

```
~/.grok/
├── config.toml           # 模型配置（供应商）+ MCP 服务器
├── AGENTS.md             # 系统提示词

├── sessions/             # 会话历史（会话管理器读取）

```

### config.toml

```toml
[models]
default = "grok-4.5"

[model."grok-4.5"]
model = "grok-4.5"
name = "My Provider"
base_url = "https://api.example.com/v1"
api_key = "sk-..."
api_backend = "responses"
context_window = 500000

[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

| 字段 | 说明 |
|------|------|
| `[models].default` | Grok Build 使用的模型配置名 |
| `[model.<配置名>]` | 该配置对应的供应商设置（见 [2.7 Grok Build](../2-providers/2.7-grok-build.md)） |
| `[mcp_servers]` | MCP 服务器配置 |

## OpenClaw 配置

### 配置目录

默认：`~/.openclaw/`

### 主要文件

```
~/.openclaw/
├── openclaw.json     # 主配置文件（JSON5 格式）
└── skills/           # 技能目录
    └── ...
```

### openclaw.json

OpenClaw 使用 JSON5 格式配置文件，主要包含以下部分：

```json5
{
  // 模型供应商配置
  models: {
    mode: "merge",
    providers: {
      "custom-provider": {
        baseUrl: "https://api.example.com/v1",
        apiKey: "your-api-key",
        api: "openai-completions",
        models: [{ id: "model-id", name: "Model Name" }]
      }
    }
  },
  // 环境变量
  env: {
    ANTHROPIC_API_KEY: "sk-..."
  },
  // Agent 默认配置
  agents: {
    defaults: {
      model: {
        primary: "provider/model"
      },
      workspace: "~/.openclaw/workspace"
    }
  },
  // 工具配置
  tools: {}
}
```

| 字段 | 说明 |
|------|------|
| `models.providers` | 供应商配置（映射为 CC Switch 的"供应商"） |
| `env` | 环境变量配置 |
| `agents.defaults` | Agent 默认模型设置 |
| `tools` | 工具配置 |
| `agents.defaults.workspace` | 工作区目录路径 |

## 配置优先级

CC Switch 修改配置时的优先级：

1. **CC Switch 数据库** - 单一事实源 (SSOT)
2. **Live 配置文件** - 切换供应商时写入
3. **回填机制** - 编辑当前供应商时从 Live 文件读取

## 手动编辑配置

### 可以手动编辑

- CLI 工具的配置文件（会被 CC Switch 回填）
- CC Switch 的 `settings.json`，但仅限 CC Switch 未运行时（设置变化时应用会重写该文件）；未知键会被忽略

### 不建议手动编辑

- `cc-switch.db` 数据库文件
- 备份文件

### 编辑后同步

如果手动编辑了 CLI 工具的配置：

1. 打开 CC Switch
2. 编辑对应的供应商
3. 会看到手动修改的内容已回填
4. 保存以同步到数据库

## 配置迁移

### 从旧版本迁移

CC Switch v3.7.0 从 JSON 文件迁移到 SQLite：

- 首次启动自动迁移
- 迁移成功后显示提示
- 旧配置文件保留作为备份

### 跨设备迁移

1. 在源设备导出配置
2. 在目标设备导入配置
3. 或使用云同步功能

## 配置备份建议

### 定期备份

建议定期导出配置：

1. 设置 → 高级 → 数据管理
2. 点击「导出」
3. 保存到安全位置

### 备份内容

导出文件包含：

- 所有供应商配置
- MCP 服务器配置
- Prompts 预设
- 应用设置

### 不包含的内容

- 用量日志（数据量大）
- 设备级设置（不适合跨设备）
