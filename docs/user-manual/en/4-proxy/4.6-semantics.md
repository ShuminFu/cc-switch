# 4.6 Proxy Semantics: What Counts as a Failure

The pages before this one describe the buttons. This page describes the rules the proxy follows,
so you can predict when it fails over, when it gives up, and what it changes on disk (DOCS-05).
The rules below are taken from `src-tauri/src/proxy/` (v3.17.0 and later).

## Which providers are tried, in which order

| Automatic failover for the app | Providers tried |
| --- | --- |
| **Off** | Only the current provider. The circuit breaker is not consulted, the phase timeouts below do not apply (only a 600 s ceiling for response headers), and errors go straight back to the tool |
| **On** | The providers in the **failover queue, in queue order** (P1 → P2 → …), skipping providers whose circuit breaker is open. The current provider is not tried first unless it is P1 |

At most `max retries + 1` providers are tried per request (default retries: 3, so up to 4
providers). When every queued provider's breaker is open the request fails with "all providers
are circuit-broken" (`FO-004`); an empty queue fails with "no providers configured" (`FO-005`).

## Which errors fail over

| Result of an attempt | Next provider? | Counts against the breaker? |
| --- | --- | --- |
| Connection refused / DNS / TLS error | Yes | Yes |
| Connect timeout (10 s) | Yes | Yes |
| Streaming: no response headers + first chunk within **first-byte timeout** | Yes | Yes |
| Streaming: no chunk for **idle timeout** after the first one (before anything reached the tool) | Yes | Yes |
| Non-streaming: no complete response within **non-streaming timeout** | Yes | Yes |
| HTTP **401, 403, 404, 408, 409, 429, 451** and every other 4xx not listed below | Yes | Yes |
| HTTP **5xx** (except 501) | Yes | Yes |
| HTTP 2xx whose body is an error envelope, or a stream that starts with an error event | Yes (fails closed instead of returning an empty reply) | Yes |
| HTTP **400, 405, 406, 413, 414, 415, 422** (the request itself is invalid) | **No**, returned to the tool | No |
| HTTP **501** (the upstream does not implement this API) | **No** | No |
| The tool cancelled the request | No | No |
| Official Codex (ChatGPT) account: 401 / 403 | **No**: the login belongs to Codex; switching providers would silently move the conversation | No |

Once the first bytes of a streamed response have been sent to the tool, the proxy cannot switch
providers any more: a later failure ends that response with an error.

Some built-in fixes (the thinking-signature and thinking-budget rectifiers) retry the **same**
provider once with a corrected request before the failure is classified as above.

## Timeouts

Configured per app in the proxy panel; `0` disables a phase. Defaults:

| Timeout | Default | Measured from |
| --- | --- | --- |
| Connect | 10 s (fixed) | Opening the TCP/TLS connection |
| Streaming first byte | 60 s | Sending the request until the first body chunk (headers included) |
| Streaming idle | 120 s | Between two chunks |
| Non-streaming | 600 s | Sending the request until the full response body |

With failover off, only the connect timeout and a 600 s ceiling for response headers apply.

## Circuit breaker

Each provider has its own breaker per app (`app:provider`). Defaults (configurable in the proxy
settings):

| State | Meaning | Leaves the state when |
| --- | --- | --- |
| **Closed** | Requests flow normally | **4 consecutive failures**, or an error rate ≥ **60 %** over the last **10** requests within 60 s → Open |
| **Open** | Provider is skipped | After **60 s** → Half-open |
| **Half-open** | One probe request at a time is let through | **2 successes** → Closed; a failure → Open again |

Only the "counts against the breaker" rows above change breaker state. Invalid requests (400,
422, …) and cancellations do not, so a broken client cannot open every breaker.

## What takeover changes on disk

When you turn on takeover for an app (4.2):

1. The current live config of that app is saved in the database (`proxy_live_backup`).
2. The live config is rewritten to point at the proxy (for example `ANTHROPIC_BASE_URL` =
   `http://127.0.0.1:15721` in Claude's `settings.json`), and the real API key is replaced by the
   placeholder `PROXY_MANAGED`. The proxy adds the real key when it forwards the request.
3. When takeover is turned off (or the proxy stops), the saved copy is written back.
4. If CC Switch crashed or was killed while an app was taken over, the next start detects the
   leftover placeholder or backup and restores the original config automatically.

While takeover is on, switching providers changes where the proxy sends requests; the tool's
own file keeps pointing at the proxy.

## Reading the logs

Every decision above is logged in `~/.cc-switch/logs/cc-switch.log` with a code, for example
`FO-004` (all providers circuit-broken). See [5.6 Troubleshooting](../5-faq/5.6-troubleshooting.md)
for log locations and [4.3 Failover](./4.3-failover.md) for the queue and health UI.
