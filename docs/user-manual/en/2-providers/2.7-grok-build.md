# 2.7 Grok Build

## Overview

[Grok Build](https://www.npmjs.com/package/@xai-official/grok) is xAI's coding CLI. Since v3.17.0 CC Switch manages it as a first-class app next to Claude Code, Codex and Gemini CLI:

| Feature | Support |
|---------|---------|
| Provider switching | Yes, writes `~/.grok/config.toml` |
| MCP servers | Yes, stored in the `[mcp_servers]` table of `config.toml` |
| Skills | Yes, installed to `~/.grok/skills/` |
| Prompts | Yes, written to `~/.grok/AGENTS.md` |
| Session Manager | Yes, reads `~/.grok/sessions/` and `~/.grok/archived_sessions/` |
| Local proxy takeover and failover | Yes |
| CLI install / update | Yes, from Settings → About (`npm i -g @xai-official/grok@latest`) |
| Project profiles | No (profiles cover Claude Code, Claude Desktop and Codex) |

If Grok Build is not shown in the app switcher, turn it on in **Settings → General → Homepage Display**.

## Configuration File

Grok Build reads a single TOML file. CC Switch owns the model selection part of it; MCP servers live in the same file and are managed from the MCP page.

```toml
[models]
default = "grok-4.5"            # client model profile that Grok Build uses

[model."grok-4.5"]
model = "grok-4.5"              # model name sent to the provider
name = "My Provider"
base_url = "https://api.example.com/v1"
api_key = "sk-..."              # or env_key = "MY_PROVIDER_API_KEY"
api_backend = "responses"       # responses / chat_completions / messages
context_window = 500000
```

CC Switch validates the file before saving a provider. The table selected by `[models].default` must exist and contain `model`, `base_url`, `name`, `api_backend`, a positive integer `context_window`, and either `api_key` or `env_key`.

The configuration directory can be moved under **Settings → Advanced → Configuration Directories → Grok Build Configuration Directory** (`grokConfigDir` in `settings.json`).

## Add a Provider

1. Select **Grok Build** in the app switcher
2. Click **+** in the top-right corner
3. Pick a preset or choose **Custom**

Grok Build reuses the third-party Codex presets (official OpenAI entries are not offered), so most OpenAI-compatible gateways are one click away.

### Form Fields

| Field | `config.toml` key | Description |
|-------|-------------------|-------------|
| Name | `name` | Display name, also written to the model table |
| API Key | `api_key` | Stored inline. Leave empty if you use `env_key` in the raw editor |
| Endpoint | `base_url` | Provider base URL |
| Client model profile | `[models].default` | Name of the profile Grok Build selects. Default `grok-4.5` |
| Model | `model` | Model sent upstream. Defaults to the profile name |
| API backend | `api_backend` | `responses` (default), `chat_completions` or `messages` (Anthropic Messages) |
| Context window | `context_window` | Positive integer, default `500000` |

The **config.toml** editor below the form shows the full document. Edits in either place are kept in sync; invalid TOML blocks saving.

## Switch Providers

Switch from the provider card, the main window, or the tray menu. CC Switch rewrites the model tables in `~/.grok/config.toml` and keeps your `[mcp_servers]` entries. A toast reminds you to **restart Grok Build** so it picks up the new provider.

## Use with the Local Proxy

Grok Build can be taken over by the local proxy like Claude Code, Codex and Gemini CLI:

- Turn on the **Grok Build** takeover switch in the proxy panel (see [4.2 App Takeover](../4-proxy/4.2-routing.md))
- While taken over, `base_url` points to `http://127.0.0.1:<port>/grokbuild/v1` and requests go through the active provider
- Failover queues, circuit breakers and usage statistics work as for the other apps (see [4.3 Failover](../4-proxy/4.3-failover.md))

## Troubleshooting

| Problem | Solution |
|---------|----------|
| "Grok Build configuration is missing [models]" | The raw `config.toml` has no `[models]` table. Fill the form fields again or add `[models] default = "..."` |
| "missing a valid api_key or env_key field" | Enter an API key, or set `env_key` to the name of an environment variable that holds it |
| Switch has no effect | Restart Grok Build; it only reads `config.toml` at startup |
| MCP servers missing in Grok Build | MCP sync only runs when `~/.grok/` exists. Start Grok Build once, then toggle the server for Grok Build on the MCP page |
