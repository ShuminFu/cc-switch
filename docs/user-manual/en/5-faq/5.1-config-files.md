# 5.1 Configuration Files

## CC Switch Data Storage

### Storage Directory

Default location: `~/.cc-switch/`

You can move it in Settings (for example into a cloud-synced folder); the chosen path is remembered in Tauri's `app_paths.json` store. `settings.json` always stays in `~/.cc-switch/`.

### Directory Structure

```
~/.cc-switch/
├── cc-switch.db      # SQLite database (SSOT)
├── settings.json     # Device-level settings
├── skills/           # Skill SSOT directory
├── skill-backups/    # Skill backups (created on uninstall)
├── backups/          # Database backups
└── logs/             # cc-switch.log (app log) and crash.log
```

### Database Contents

`cc-switch.db` is a SQLite database that stores:

| Table | Contents |
|-------|----------|
| providers | Provider configurations (per app) |
| provider_endpoints | Provider endpoint candidate list |
| mcp_servers | MCP server configurations and per-app toggles |
| prompts | Prompt presets |
| skills | Installed skills and per-app toggles |
| skill_repos | Skill repository list |
| profiles | Project profiles (named snapshots of provider/MCP/Skills/prompt state) |
| settings | Key-value app state that syncs with the database (common config snippets, current profile, ...) |
| proxy_config | Local proxy, failover and circuit-breaker settings (one row per proxied app) |
| proxy_live_backup | Copy of each app's live config taken while the proxy has taken it over |
| provider_health | Provider health / failover state |
| proxy_request_logs | Per-request usage logs (proxy and session sync) |
| usage_daily_rollups | Daily usage aggregates kept after detailed logs are pruned |
| session_log_sync | Read offsets for CLI session logs imported into usage statistics |
| stream_check_logs | Provider stream health-check results |
| model_pricing | Model pricing used for cost calculation |

### Device Settings

`settings.json` stores device-level settings that are **not** synced across devices. Keys are camelCase and match `AppSettings` in `src-tauri/src/settings.rs`. Keys that are unset are omitted from the file. A typical file:

```json
{
  "showInTray": true,
  "minimizeToTrayOnClose": true,
  "useAppWindowControls": false,
  "launchOnStartup": false,
  "silentStartup": false,
  "language": "en",
  "visibleApps": {
    "claude": true,
    "claude-desktop": true,
    "codex": true,
    "gemini": true,
    "grokbuild": true,
    "opencode": true,
    "openclaw": true,
    "hermes": false
  },
  "enableClaudePluginIntegration": false,
  "skipClaudeOnboarding": false,
  "enableLocalProxy": false,
  "enableFailoverToggle": false,
  "showProfileSwitcher": true,
  "preserveCodexOfficialAuthOnSwitch": false,
  "unifyCodexSessionHistory": false,
  "claudeConfigDir": "/custom/path/.claude",
  "currentProviderClaude": "my-provider-1730000000000",
  "skillSyncMethod": "auto",
  "skillStorageLocation": "cc_switch",
  "backupIntervalHours": 24,
  "backupRetainCount": 10,
  "preferredTerminal": "iterm2"
}
```

Main keys:

| Key | Default | Meaning |
|-----|---------|---------|
| `showInTray` / `minimizeToTrayOnClose` | `true` / `true` | Tray icon; close button hides to tray instead of quitting |
| `useAppWindowControls` | `false` | Use the app's own title-bar buttons |
| `launchOnStartup` / `silentStartup` | `false` | Start at login; start hidden in the tray |
| `language` | system | `en`, `zh`, `zh-TW` or `ja` |
| `visibleApps` | all except Hermes | Which apps are shown on the main page |
| `enableClaudePluginIntegration` | `false` | Also switch the Claude Code VS Code extension |
| `skipClaudeOnboarding` | `false` | Skip Claude Code's first-run confirmation |
| `enableLocalProxy` / `enableFailoverToggle` | `false` | Show the local proxy and failover controls on the main page |
| `showProfileSwitcher` | `true` | Show the project switcher in the header |
| `preserveCodexOfficialAuthOnSwitch` / `unifyCodexSessionHistory` | `false` | Codex official-login and session-history options |
| `claudeConfigDir`, `codexConfigDir`, `geminiConfigDir`, `grokConfigDir`, `opencodeConfigDir`, `openclawConfigDir`, `hermesConfigDir` | unset | Override each tool's config directory |
| `currentProvider<App>` | unset | Current provider id per app on this device (takes priority over the database) |
| `skillSyncMethod` / `skillStorageLocation` | `auto` / `cc_switch` | How skills are linked into apps (`auto`, `symlink`, `copy`) and where they are stored (`cc_switch` or `unified` = `~/.agents/skills/`) |
| `webdavSync` / `s3Sync` | unset | Cloud sync settings (including credentials) |
| `backupIntervalHours` / `backupRetainCount` | `24` / `10` | Automatic database backup interval (`0` disables) and how many backups to keep |
| `preferredTerminal` | system default | Terminal used to open sessions |

`proxyConfirmed`, `usageConfirmed`, `failoverConfirmed`, `firstRunNoticeConfirmed` and `commonConfigConfirmed` record which first-run notices you have dismissed; `localMigrations` records one-off migrations already run on this device.

The UI theme is **not** in `settings.json`: it is kept in the app's browser storage (`localStorage` key `cc-switch-theme`).

### Automatic Backups

The `backups/` directory stores automatic backups:

- Created periodically (every `backupIntervalHours`, default 24 hours) and before database migrations and SQL imports
- Retains the most recent `backupRetainCount` backups (default 10)
- File names include timestamps; you can restore, rename or delete them in Settings

## Claude Code Configuration

### Configuration Directory

Default: `~/.claude/`

### Key Files

```
~/.claude/
├── settings.json     # Main configuration file
├── CLAUDE.md         # System prompt
└── skills/           # Skills directory
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxx",
    "ANTHROPIC_BASE_URL": "https://api.example.com",
    "ANTHROPIC_MODEL": "example-model"
  },
  "permissions": {
    "allow": ["Bash(git status)"]
  }
}
```

| Field | Description |
|-------|-------------|
| `env.ANTHROPIC_AUTH_TOKEN` | API key (what CC Switch writes for most providers) |
| `env.ANTHROPIC_API_KEY` | API key, alternative variable used by some providers |
| `env.ANTHROPIC_BASE_URL` | API endpoint (omit for the official API) |
| `env.ANTHROPIC_MODEL`, `env.ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL` | Model overrides |
| `permissions.allow` / `permissions.deny` | Claude Code tool permission rules (lists of strings) |

### MCP Configuration

MCP server configuration is in `~/.claude.json`:

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Codex Configuration

### Configuration Directory

Default: `~/.codex/`

### Key Files

```
~/.codex/
├── auth.json         # Authentication configuration
├── config.toml       # Main configuration + MCP
└── AGENTS.md         # System prompt
```

### auth.json

```json
{
  "OPENAI_API_KEY": "sk-xxx"
}
```

### config.toml

CC Switch writes third-party providers under `model_provider = "custom"` with a `[model_providers.custom]` table:

```toml
model_provider = "custom"
model = "gpt-5.5"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.custom]
name = "My Provider"
base_url = "https://api.example.com/v1"
wire_api = "responses"
requires_openai_auth = true

# MCP servers
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

## Hermes Configuration

### Configuration Directory

Default: `~/.hermes/`

### Key Files

```
~/.hermes/
├── config.yaml       # Main settings, providers, and MCP configuration
├── .env              # API keys and secrets
├── SOUL.md           # Profile identity/persona
├── memories/
│   ├── MEMORY.md     # Agent memory
│   └── USER.md       # User profile memory
├── skills/           # Active skills directory
├── state.db          # SQLite session database
└── sessions/         # Gateway transcripts and optional JSON snapshots
```

### config.yaml

Hermes uses YAML configuration. CC Switch writes MCP servers to `mcp_servers`, writes editable provider entries to `custom_providers`, reads read-only entries from Hermes' `providers` dict, and updates `model.provider` / `model.default` when switching providers.

## OpenClaw Configuration

### Configuration Directory

Default: `~/.openclaw/`

### Key Files

```
~/.openclaw/
├── openclaw.json     # Main configuration file (JSON5 format)
└── skills/           # Skills directory
    └── ...
```

### openclaw.json

OpenClaw uses a JSON5 format configuration file with the following main sections:

```json5
{
  // Model provider configuration
  models: {
    mode: "merge",
    providers: {
      "custom-provider": {
        baseUrl: "https://api.example.com/v1",
        apiKey: "your-api-key",
        api: "openai-completions",
        models: [{ id: "model-id", name: "Model Name" }]
      }
    }
  },
  // Environment variables
  env: {
    ANTHROPIC_API_KEY: "sk-..."
  },
  // Agent default configuration
  agents: {
    defaults: {
      model: {
        primary: "provider/model"
      },
      workspace: "~/.openclaw/workspace"
    }
  },
  // Tool configuration
  tools: {}
}
```

| Field | Description |
|-------|-------------|
| `models.providers` | Provider configuration (mapped to CC Switch's "providers") |
| `env` | Environment variable configuration |
| `agents.defaults` | Agent default model settings |
| `tools` | Tool configuration |
| `agents.defaults.workspace` | Workspace directory path |

## Configuration Priority

CC Switch's priority when modifying configurations:

1. **CC Switch Database** - Single source of truth (SSOT)
2. **Live Configuration Files** - Written when switching providers
3. **Backfill Mechanism** - Reads from live files when editing the current provider

## Manual Configuration Editing

### Safe to Edit Manually

- CLI tool configuration files (will be backfilled by CC Switch)
- CC Switch's `settings.json`, but only while CC Switch is closed (the app rewrites the file when settings change); unknown keys are ignored

### Not Recommended to Edit Manually

- `cc-switch.db` database file
- Backup files

### Sync After Editing

If you manually edit CLI tool configurations:

1. Open CC Switch
2. Edit the corresponding provider
3. You will see the manual changes have been backfilled
4. Save to sync to the database

## Configuration Migration

### Migrating from Older Versions

CC Switch v3.7.0 migrated from JSON files to SQLite:

- Automatic migration on first launch
- Displays a notification upon successful migration
- Old configuration files are retained as backups

### Cross-device Migration

1. Export configuration on the source device
2. Import configuration on the target device
3. Or use the cloud sync feature

## Configuration Backup Recommendations

### Regular Backups

It is recommended to regularly export configurations:

1. Settings > Advanced > Data Management
2. Click "Export"
3. Save to a secure location

### Backup Contents

The export file includes:

- All provider configurations
- MCP server configurations
- Prompt presets
- App settings

### Not Included

- Usage logs (large data volume)
- Device-level settings (not suitable for cross-device)
