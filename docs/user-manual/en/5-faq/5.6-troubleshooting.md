# 5.6 Troubleshooting

One place per operating system: symptoms, fixes, and which files to attach to a bug report.
For feature questions see [5.2 FAQ](./5.2-questions.md).

## Logs and crash log

CC Switch writes everything below its data directory (`~/.cc-switch`, or the directory you chose
in Settings → Advanced → Configuration Directories).

| File | macOS / Linux | Windows | Contents |
| --- | --- | --- | --- |
| App log | `~/.cc-switch/logs/cc-switch.log` (rotated) | `%USERPROFILE%\.cc-switch\logs\cc-switch.log` | Everything the app does, including the local proxy (requests, failover, circuit breaker). The level is set in Settings → Advanced → Log Configuration |
| Crash log | `~/.cc-switch/crash.log` | `%USERPROFILE%\.cc-switch\crash.log` | Panic message and backtrace when the app crashes |
| Proxy request log | inside `cc-switch.db` | inside `cc-switch.db` | Per-request status, latency and tokens; view it in the Usage dashboard (see [4.4](../4-proxy/4.4-usage.md)) |

**Before attaching logs to a public issue**, remove API keys, tokens and base URLs you do not
want to share. At the default `info` level secrets are redacted, but `debug`/`trace` logs,
provider configs (`settings.json`, `auth.json`, `.env`) and screenshots can contain them.

### Run from a terminal to see startup errors

Errors that happen before the window opens are printed to the terminal:

- **macOS**: `/Applications/CC\ Switch.app/Contents/MacOS/cc-switch`
- **Linux**: `cc-switch` (deb/rpm) or `./CC-Switch-*.AppImage`
- **Windows** (PowerShell): `& "$env:LOCALAPPDATA\Programs\CC Switch\cc-switch.exe"`

## Windows

| Symptom | Fix |
| --- | --- |
| "Windows protected your PC" (SmartScreen) | The build is not Authenticode-signed. Choose "More info" → "Run anyway". Verify the file first with `SHA256SUMS` ([SECURITY.md](../../../../SECURITY.md#verifying-a-download)) |
| App does not start after installing | Install the [WebView2 runtime](https://developer.microsoft.com/microsoft-edge/webview2/); allow CC Switch in your antivirus |
| Wrong build for an ARM PC | Use the `-Windows-arm64.msi` / `-arm64-Portable.zip` assets |
| Portable build: no in-app update | Download the new `-Portable.zip` and replace `cc-switch.exe` (keep `portable.ini` next to it); your data stays in `%USERPROFILE%\.cc-switch` |
| Proxy cannot start: port in use | Another program (or a second CC Switch) uses port 15721. Change the port in the proxy panel, or find the process with `netstat -ano | findstr 15721` |
| Update fails | Download the MSI from the Releases page and install it over the existing version; your data in `%USERPROFILE%\.cc-switch` is kept |

## macOS

| Symptom | Fix |
| --- | --- |
| "Cannot be opened because the developer cannot be verified" | Should not happen: builds are signed and notarized. Make sure you downloaded from the official Releases page or Homebrew, then try again |
| Tray icon missing | Too many menu bar items: hide some, or use a menu bar manager |
| App does not start | Run it from a terminal (above) and look at `~/.cc-switch/crash.log` |
| Proxy cannot start: port in use | `lsof -nP -iTCP:15721 -sTCP:LISTEN` shows the process; change the port or stop it |

## Linux

| Symptom | Fix |
| --- | --- |
| AppImage does not start | `chmod +x CC-Switch-*.AppImage`; on systems without FUSE 2 run `./CC-Switch-*.AppImage --appimage-extract-and-run` |
| `.deb`/`.rpm` fails with missing `libwebkit2gtk-4.1` or glibc symbols | The packages need glibc 2.35+ and WebKitGTK 4.1 (Ubuntu 22.04+, Debian 12+, Fedora 36+). Use the AppImage on older systems |
| Clicks do not register / black window on resize (Wayland + NVIDIA) | Start with `CC_SWITCH_GDK_BACKEND=wayland` (or `=x11` on sway/Hyprland). See [5.2](./5.2-questions.md) |
| Blank or flickering window | Try `WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 cc-switch` (the app already sets these by default; setting them explicitly overrides nothing else) |
| Slow scrolling or high CPU with a recent WebKitGTK (GPU works) | Start with `CC_SWITCH_WEBKIT_GPU=1 cc-switch` to keep WebKitGTK's GPU compositing and DMA-BUF renderer, which the app otherwise turns off. Remove it if the window turns blank |
| Tray icon missing (GNOME) | Install the "AppIndicator and KStatusNotifierItem Support" extension |
| `ccswitch://` links do not open the app | Run `xdg-mime default <cc-switch desktop file> x-scheme-handler/ccswitch` (the desktop file name is in `/usr/share/applications/`) |
| Flatpak: tools "not installed", terminal does not open | Known sandbox limitation, see [`flatpak/README.md`](../../../../flatpak/README.md) |
| Proxy cannot start: port in use | `ss -ltnp | grep 15721` shows the process; change the port or stop it |

## All platforms

| Symptom | Fix |
| --- | --- |
| The app shows an error about an unreadable configuration file and exits | A file in `~/.cc-switch` is damaged. See [5.1 Manual restore](./5.1-config-files.md#manual-restore-when-the-app-does-not-start) |
| A switch does not take effect | Restart the CLI tool; check for overriding environment variables ([5.4](./5.4-env-conflict.md)) |
| Failover does not trigger / triggers too often | See [4.6 Proxy Semantics](../4-proxy/4.6-semantics.md) for which errors count |
| A tool still points at `127.0.0.1:15721` after CC Switch crashed or was killed | Start CC Switch again: on start-up it detects the leftover takeover and restores the original live config from its backup |

## Filing a bug report

Use the [bug report form](https://github.com/farion1231/cc-switch/issues/new?template=bug_report.yml).
It asks for the version, OS and architecture, installation method and app language; attach the
app log and, after a crash, `crash.log`, with secrets removed.
