# 5.5 Command Line (`ccs`) and Headless Proxy

## Overview

`ccs` lets you use CC Switch from a terminal: in scripts, dotfiles, tmux, or over SSH. It reads and writes the same data as the desktop app, so switching a provider with `ccs` changes your CLI config files exactly like clicking the provider in the app.

The desktop app can also run only its local proxy, without a window or tray icon, for servers, WSL and other machines without a desktop.

## Everyday commands

| Command | What it does |
|---------|--------------|
| `ccs ls` | List providers for every app; `*` marks the current one |
| `ccs ls claude` | List Claude Code providers |
| `ccs current` | Show the current provider of each app |
| `ccs switch claude packycode` | Switch Claude Code to the provider with id or name "packycode" |
| `ccs usage summary --days 7` | Requests, tokens and cost for the last 7 days |
| `ccs export backup.sql` | Save a backup (same as Settings → Export) |
| `ccs import backup.sql` | Restore a backup (same as Settings → Import) |

App names: `claude`, `claude-desktop`, `codex`, `gemini`, `grokbuild`, `opencode`, `openclaw`, `hermes`.

Add `--json` to any command to get output that scripts can read, for example:

```bash
ccs --json current codex
```

## Using `ccs` while the app is open

You can always **look** (`ls`, `current`, `usage`, `export`, `proxy status`) while the desktop app is running.

Commands that **change** things (`switch`, `import`, `proxy start`) are refused while the app is open, including when it is minimized to the tray, so the two never edit your config files at the same time. You will see a message like:

```
ccs: The CC Switch database is in use by the CC Switch desktop app (pid 4242).
Make the change in the desktop app (window or tray menu), or quit it and run the command again.
```

Changes you make with `ccs` while the app is closed appear the next time you open it.

## Custom data directory

If you moved the CC Switch data directory in Settings → Directories, `ccs` uses the same directory automatically. To point it somewhere else, use `--config-dir /path/to/dir` or set the `CC_SWITCH_CONFIG_DIR` environment variable.

## Headless proxy

Run the proxy without the desktop app:

```bash
ccs proxy start          # or: cc-switch --headless
```

- Apps whose **takeover** switch is on in Settings → Proxy are taken over again, just like when the app starts. Use `--no-takeover` to start only the proxy.
- Press **Ctrl-C**, or run `ccs proxy stop` from another terminal, to stop it. Your CLI config files are restored to the direct provider settings, and takeover resumes on the next start.
- `ccs proxy status` shows whether the proxy is running and who runs it (the app or a headless proxy).

Don't run the headless proxy and the desktop app at the same time; they would both try to use the proxy port. Stop the headless proxy before opening the app.

> To keep the proxy running on a Linux server, start `ccs proxy start` from a systemd user service. See `docs/cli.md` in the repository for an example unit file and the full command reference.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | The command failed |
| 2 | Invalid arguments |
| 3 | The desktop app, a headless proxy or another `ccs` command is currently changing data |
