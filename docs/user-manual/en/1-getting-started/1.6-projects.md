# 1.6 Projects (Project Profiles)

## Overview

A **project** is a named snapshot of your configuration. Instead of switching the provider, then toggling MCP servers, then Skills, then the memory file one by one, you save the combination once and switch it back in one click.

Projects were introduced in v3.17.0 and are available on every app tab:

| App tab | What a project captures |
|---------|-------------------------|
| Claude Code | Current provider, enabled MCP servers, enabled Skills, active prompt (memory file `CLAUDE.md`) |
| Codex | Current provider, enabled MCP servers, enabled Skills, active prompt (memory file `AGENTS.md`) |
| Gemini | Current provider, enabled MCP servers, enabled Skills, active prompt (memory file `GEMINI.md`) |
| Grok Build | Current provider, enabled MCP servers, enabled Skills, active prompt (memory file `AGENTS.md`) |
| OpenCode, Hermes | Enabled MCP servers, enabled Skills, active prompt. These apps load every provider at once, so there is no "current provider" to save |
| OpenClaw | Active prompt only (OpenClaw has no MCP or Skills support in CC Switch, and loads every provider at once) |
| Claude Desktop | Current provider only (the other dimensions are not managed by CC Switch for Claude Desktop) |

Projects saved with an older version only contain the Claude Code, Claude Desktop and Codex slots. On the other tabs they show **Not saved for this app yet** until you leave them once.

## Project Switcher

On a supported tab, the project switcher sits in the header next to the app switcher. It shows the project that is current for that tab, or **No project**.

Click it to:

- Pick a project to apply it
- Pick **No project** to go back to the configuration you had before you started using projects on this tab (see below)
- Search projects by name
- **New project**: save the current configuration of this tab as a new project
- **Manage projects…**: rename or delete projects

The same list is available from the tray menu under **Projects**, with one submenu per tab.

> You can hide the header switcher under **Settings → General → Homepage Display → Show project switcher**. Projects and the tray **Projects** submenu keep working when it is hidden.

## Projects Are Shared, Switching Is Per Tab

A project is one global entity, but it stores a separate slot for each tab:

- Applying a project on the **Codex** tab only changes Codex. Claude Code and Claude Desktop keep their configuration and their own current project.
- A project that was never saved for a tab shows **Not saved for this app yet** in the manage dialog. Applying it there only marks it as current; nothing is changed until you leave it, at which point the configuration is saved into it.

## Going Back to "No Project"

The first time you apply a project on a tab that shows **No project**, CC Switch first saves the tab's current configuration as a private *before projects* snapshot. Picking **No project** later saves your changes back into the current project, restores that snapshot (provider, MCP servers, Skills and prompt) and then discards it. The next time you apply a project from **No project**, a new snapshot is taken.

If there is no snapshot (for example the project was applied with an older version), **No project** only stops tracking the current project and does not change your configuration.

The snapshot is device-local: WebDAV / S3 sync downloads do not overwrite it.

## Autosave When Switching

When you switch from project A to project B on a tab, CC Switch first saves the tab's current configuration back into project A, then applies project B. A project therefore always holds the configuration you last left it in, which is why there is no "update snapshot" button: just edit providers, MCP, Skills or prompts while the project is current and switch away.

## What Happens When a Project Is Applied

1. Proxy takeover is turned off for the apps of that tab (OpenCode, OpenClaw and Hermes have no takeover). If no other app is still taken over and Claude Desktop is not using local routing, the local proxy is stopped. Turn takeover back on afterwards if you need it.
2. The saved provider is switched in, exactly as if you clicked **Enable** on its card.
3. MCP servers and Skills are enabled or disabled so that they match the snapshot. Only the differences are applied.
4. The saved prompt is activated.

Applying is best effort. If the snapshot refers to something that no longer exists (for example a deleted provider or an uninstalled skill), that item is skipped and the result shows **Project applied with N warning(s)** with the details. Nothing is rolled back.

## Manage Projects

**Manage projects…** opens a dialog listing every project:

| Action | Description |
|--------|-------------|
| Rename | Change the project name |
| Delete | Remove the project. Your current configuration is not changed |

## Directory Bindings

You can bind a folder to a project, so the right configuration is one click away when you work in that folder. Open **Manage projects…** and use the **Directory bindings** section:

1. Choose the project to bind.
2. Optionally turn on **Write project files** (see below).
3. Click **Bind folder…** and pick the folder. If the folder is inside a git repository, the binding is stored for the repository root, so it also covers every subfolder.

Each binding has an **Apply now** button and a **Remove binding** button. When bindings are nested, the most specific folder wins. Removing a binding never changes files in the folder. Deleting a project also removes its bindings.

Bindings are stored only in the CC Switch database on this device. CC Switch never writes a marker file into your repository.

### Global Configuration or Project Files

How a binding is applied depends on the app and on **Write project files**:

| App | Write project files off | Write project files on |
|-----|-------------------------|-------------------------|
| Claude Code | The project is applied to the Claude Code tab, exactly like picking it in the switcher | The provider settings of the project (the `env` block) are written to `<folder>/.claude/settings.local.json`. Your global `~/.claude/settings.json` and current provider stay as they are |
| Gemini | Applied to the Gemini tab | The provider variables of the project are written to `<folder>/.gemini/.env`, which Gemini CLI reads before `~/.gemini/.env` |
| Every other app | Applied to that app's tab | Applied to that app's tab. These apps have no project-level configuration file that CC Switch can use |

With project files, two terminals in two different folders can use two different providers at the same time, because nothing global changes. In project-file mode only the provider is written; MCP servers, Skills and prompts are not changed. Restart the CLI in that folder after applying.

Safety rules for project files:

- CC Switch writes only those two fixed paths inside the bound folder. It refuses to write if `.claude`, `.gemini` or the file itself is a symbolic link, or if the path would end up outside the folder.
- Before changing a file that already exists, CC Switch saves a copy next to it named `<file>.ccswitch-backup-<date>-<time>`. If the copy cannot be written, the file is not changed. If nothing would change, nothing is written and no copy is made.
- Only the keys CC Switch wrote are added, updated or removed. Your own settings in the file (for example `permissions`, or your own variables in `.env`) are kept. A file that is not valid JSON is never rewritten.
- These files contain your API key. Claude Code keeps `settings.local.json` out of git by default; for Gemini, make sure `.gemini/.env` is listed in your `.gitignore`.

Switching automatically when you `cd` into a folder needs a command-line companion that is not available yet. Until then, use **Apply now**.

## Sync and Backup

Projects are stored in the `profiles` table of `~/.cc-switch/cc-switch.db`, so they are included in database backups, SQL export, and WebDAV / S3 sync. The "current project" marker of each tab, the *before projects* snapshot and the directory bindings are device-local, and a sync download does not overwrite them.

## Tips

- Create a project per client or per repository, for example "Work (company gateway)" and "Personal (own key)".
- Before switching a project, finish any running CLI session: the CLI keeps using the old configuration until it is restarted.
