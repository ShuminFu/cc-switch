# CCS-180: [ipc] Register commands per domain with collect_commands! and scope them with AppManifest permissions

**Status:** Done · **Kind:** security · **Labels:** `security`, `phase:P5`, `p2-medium`, `area:ipc`

> **Ticket key:** `p5-command-domains-permissions` · **Phase:** P5 · **Priority:** p2-medium · **Effort:** M · **Depends on:** `p5-misc-split-terminal`, `p2-bindings-generate`, `p1-ipc-path-validation`
> Plan: [next-phase-plan.md](../../next-phase-plan.md)

## Problem
Verified finding ci-ipc-commands-open, partially real. All ~289 commands are callable from the webview, including file-writing primitives. The strict CSP makes exploitation hard, so this is defence in depth. The critique sequences it after the domain split.

## Evidence
- src-tauri/build.rs:2 plain tauri_build::build(); capabilities/default.json; lib.rs generate_handler

## Proposed change
- Add commands/<domain>/ folders using collect_commands!.
- build.rs uses `try_build(Attributes::new().app_manifest(AppManifest::new().commands(&[...])))`.
- Add src-tauri/permissions/<domain>.toml, and put privileged commands (env restore/delete, terminals, file writers) in a separate set that is not in default.json.

## Acceptance criteria / verification
- [x] `cargo build` produces gen/schemas listing the app permissions
- [x] From devtools, invoking a command that was not granted fails with "not allowed"
- [x] tauri-driver smoke is green

## Dependencies
p5-misc-split-terminal, p2-bindings-generate, p1-ipc-path-validation

## Implementation notes

**Summary.** The 298 registered commands are now listed per domain in one
registry, `src-tauri/src/commands/registry.rs` (`for_each_command_domain!`).
`lib.rs` expands it into `tauri::generate_handler!`. `build.rs` `include!`s the
same file, passes every command name to
`tauri_build::try_build(Attributes::new().app_manifest(AppManifest::new().commands(..)))`
and writes one `[[set]]` per domain to `src-tauri/permissions/<domain>.toml`.
Because the app now has an ACL manifest, Tauri checks every app command against
the capabilities. A command outside every granted set is rejected with
"... not allowed".

- Standard domains (`app`, `settings`, `config`, `provider`, `accounts`, `mcp`,
  `prompt`, `profile`, `skill`, `proxy`, `usage`, `sync`, `sessions`,
  `cli-tools`, `integrations`) are granted by `capabilities/default.json`.
- Privileged domains are granted only by the new
  `capabilities/privileged.json` (main window, local origin), never by
  default.json:
  - `privileged-env`: `delete_env_vars`, `restore_env_backup`
  - `privileged-terminal`: provider/session terminals, Hermes dashboard,
    `run_tool_lifecycle_action`
  - `privileged-file-write`: CSV/config export and import, zip skill import,
    DB backup restore/rename/delete, config dir override, OpenClaw
    workspace/daily-memory writes
- `src-tauri/permissions/autogenerated/` (per-command `allow-*`/`deny-*`,
  rewritten by tauri-build on each build) is gitignored. The domain set files
  are committed so changes to what is granted show up in review. CI's
  "Check generated bindings" step also fails if they are stale.
- Kept from the plan, with one change: the command implementations stay in
  their existing `commands/*.rs` files. Domains are groupings in the
  registry, not `commands/<domain>/` folders. `tauri_specta::collect_commands!`
  is test-only here (specta is a dev-dependency, see
  `docs/dev/adr/bindings.md`), so it cannot drive the runtime handler. Moving
  the files would also have collided with the concurrent
  `services/proxy`/`commands/proxy.rs` work. New commands go in `registry.rs`,
  not `lib.rs`.
- Consumers of the old `generate_handler!` list in `lib.rs` now read the
  registry: `bindings.rs` `COMMANDS`, regenerated `src/shared/bindings.ts`
  (order only), `scripts/check-ipc-orphans.mjs` and its test.
- The e2e smoke gains a step that invokes a command no capability grants from
  the webview (`window.__TAURI_INTERNALS__.invoke`, the same call as from
  devtools) and expects `not allowed`.

**Verification.**
- `cargo build`: `gen/schemas/acl-manifests.json` has an `__app-acl__` entry
  with 596 permissions (allow/deny for each of the 298 commands) and all 18
  domain sets. `desktop-schema.json` lists them.
- `cargo test --lib acl_tests`: 5 passed. These tests build a mock app from
  the real `generate_context!(test = true)`. They cover: granted commands work

  `not allowed`; standard and privileged commands are `not allowed` from
  another window or a remote origin; each command is in exactly one domain;
  default.json grants exactly the standard sets and privileged.json exactly
  the privileged ones.

  3 of 5 failed. The two ACL tests failed because ungranted commands resolved
  with `ok`, and the capability split test also failed. So these are
  regression tests.

  `cargo clippy --all-targets -- -D warnings`: clean.
- `cargo test --no-fail-fast` (full suite): 3045 passed, 0 failed.
- `pnpm typecheck`: ok. `pnpm test:unit`: 165 files / 1573 tests passed.
