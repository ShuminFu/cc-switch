# Porting conventions for `cc-switch-ui`

Read this before porting a React area. Specs of the React behaviour live in
`docs/dev/specs/`.

## Layout

```
src/main.rs            module list, stylesheets, launch
src/shell/             title bar, app switcher, header actions, ViewRouter
src/views/<area>/      one module per React area (providers, settings, mcp, ...)
src/widgets/           small shared widgets (ProviderIcon, ...)
src/components/        vendored dioxus-primitives wrappers (dx components add) — do not hand-edit
src/api/<module>.rs    typed invoke wrappers, generated from src/lib/api/*.ts; edit freely
src/query.rs           use_query(key_fn, fetch_fn) + QueryClient::invalidate*
src/state.rs           AppState { settings, active_app, view, locale } via use_app_state()
src/i18n.rs            t!("key"), t!("key", name = value); keys are the React JSON keys
src/icons/             icon set generated by `pnpm icons:emit-rust`
src/events.rs          use_tauri_event::<Payload, _>(events::NAME, handler)
```

## Rules

- Translations: never hard-code user-facing text; use the same key the TSX used
  (`t!`). If a key is missing in `src/i18n/locales/en.json`, add it to all four
  locale files (the React app reads them too).
- Data: read through `use_query(|| key, || api::x::y(..))`. Keys live in
  `query::keys`. Mutations call the API then `queries.invalidate(..)` exactly
  where the React mutation invalidated (see the spec tables).
- Reactive props: a prop that drives a query must be `ReadSignal<T>` and read
  inside the closures (`app()`), otherwise the query is stuck on the first value.
- Types: prefer contract types (`cc_switch_contract::*`); when a payload is still
  `serde_json::Value`, add the struct to the contract crate and a round-trip test
  in `src-tauri/tests/ipc_contract.rs` if the backend has the same struct.
- Shared logic: TOML/JSON config manipulation is in `cc_switch_config`;
  preset catalogs and helpers are in `cc_switch_presets`. Do not reimplement.
- Toasts: `let toast = use_toast(); toast.success(title, ToastOptions::new().description(..))`
  from `dioxus_primitives::toast`. Dialogs/menus/selects: use `crate::components::*`.
- Styling: Tailwind classes copied from the TSX; tokens (`bg-background`,
  `text-muted-foreground`, `glass-card`, ...) come from `assets/base.css`.
- Icons: `dioxus_icons::lucide::Name { size: "16px" }`; brand icons via
  `widgets::ProviderIcon`.
- Tests: pure logic (sorting, filtering, mapping) gets `#[cfg(test)]` unit tests
  and runs natively with `cargo test -p cc-switch-ui`; user flows are covered by
  `e2e/smoke.mjs` against the Tauri mock (`e2e/tauri-mock.js`, extend `handlers`).
- Before finishing: `cargo fmt --all`, `cargo clippy -p cc-switch-ui --target
  wasm32-unknown-unknown -- -D warnings`, `cargo test -p cc-switch-ui`, and
  `dx build --platform web --release` from `crates/cc-switch-ui`.
